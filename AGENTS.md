# AGENTS.md — El Gato Bobah POS

Estándares de ingeniería del repo. Fuente **canónica** y vendor-neutral (estándar
[agents.md](https://agents.md)); las herramientas de IA (Claude Code, Cursor, etc.) leen esto.
Reglas concretas y verificables: documentan lo que **no** se infiere del código y el **porqué**.
Ante duda, el código real manda — cada regla apunta a un ejemplo (`archivo:símbolo`).

## 1. Proyecto y stack

POS propio para un solo local (reemplaza a FUDO). Monorepo:

- **`server/`** — Go 1.25 · chi · pgx + **sqlc** · goose (migraciones **embebidas**) · Redis (solo caché de menú).
- **`web/`** — React 19 · Vite · Chakra UI v3 · TanStack Query · Zustand. Bun, **nunca npm**.
- **`deploy/`** — docker-compose + Caddy (TLS, headers de seguridad).

## 2. Comandos (todos en `Makefile`; `make help` los lista)

- `make install` — setup completo (valida entorno, instala deps y herramientas). `make check` solo verifica prereqs.
- `make start` — levanta todo: Postgres **:5433**, Redis **:6380** (puertos no estándar para no chocar con otros contenedores), API y web (Vite en http://localhost:3000).
- `make api-dev` (hot reload con air) · `make api-build` (= `cd server && go build ./...`) · `make api-test` (= `cd server && go test ./...`).
- `make web-dev` · `make web-build` · `make web-test` (vitest).
- `make lint` (golangci-lint + gosec) · `make vuln` (govulncheck) · `make web-lint` (eslint + tsc) · `make sec` (todos).
- `make sqlc` (regenera código de queries) · `make migrate-new name=xxx` (nueva migración goose).
- **Frontend siempre con bun** (`bun install`, `bun run`, `bun audit`). `web/package.json` bloquea npm (`preinstall: only-allow bun`). Nunca crees `package-lock.json`.

## 3. Arquitectura — dónde vive qué

Request → **`httpapi`** (handler fino) → **`app`** (servicio, orquesta + tx) → **`store/db`** (sqlc) ; lógica pura en **`domain`**.

- **`httpapi/`** — handlers finos: decodifican body, construyen el `cmd`, llaman al servicio, mapean el error y responden JSON. Sin lógica de negocio. Ej.: [`Handlers.CreateOrder`](server/internal/httpapi/handlers_orders.go). Rutas y middleware en [`Router`](server/internal/httpapi/router.go).
- **`app/`** — servicios: orquestan dominio + store, manejan transacciones con `store.WithTx(ctx, func(q *db.Queries) error{…})`. Ej.: [`OrdersService.Cancel`](server/internal/app/orders.go).
- **`domain/`** — **puro, sin I/O** (nada de DB/HTTP/red): tipos, sentinels, reglas y cálculo. Ej.: [`BuildOrder`](server/internal/domain/order.go), [`CanTransition`](server/internal/domain/order.go).
- **`store/db/`** — **generado por sqlc** (`// Code generated by sqlc. DO NOT EDIT.`). Cambias `queries/*.sql` + `make sqlc`, nunca el `.go`.
- Migraciones goose **embebidas** en el binario. Redis es **solo caché de menú** — nunca fuente de verdad.

## 4. Backend Go

- **Errores: envuelve con `%w` y usa sentinels de `domain`.** Ej.: `fmt.Errorf("%w (id %d)", ErrProductNotSell, in.ProductID)` en [order.go](server/internal/domain/order.go); el mapeo a HTTP vive **solo** en [`httpapi.Error`](server/internal/httpapi/respond.go) vía `errors.Is`. No repartas `http.Error` por los handlers.
- **`context.Context` es el primer parámetro y se propaga** hasta la query (pgx lo respeta). Nunca `context.Background()` dentro de un request.
- **Handler fino, lógica en servicio, reglas/estado en `domain`.** Una transición de orden se decide en [`domain.CanTransition`](server/internal/domain/order.go), no en el handler.
- **Dinero = `float64` en pesos, redondeado en cada frontera con [`domain.Round2`](server/internal/domain/money.go) (2dp) / `Round4` (stock, 4dp) y validado con `domain.ValidMoney` antes de tocar una columna `numeric`.** No son centavos enteros; el techo conocido está documentado en `money.go` (migrar a `int64` si el redondeo falla en sumas grandes). El servidor **siempre** re-calcula precios; los del cliente se ignoran ([`BuildOrder`](server/internal/domain/order.go)).
- **SQL solo vía sqlc.** Nunca concatenes ni interpoles SQL a mano — todo parametrizado.
- **Valida input y cotas en la frontera** (§5).
- Sin fugas de goroutines: toda goroutine tiene una condición de término (ctx o cierre de canal).

## 5. Seguridad

Este repo pasó una auditoría OWASP + una segunda ronda adversarial ([docs/security-owasp.md](docs/security-owasp.md)). Estos helpers **ya existen**: úsalos, no reinventes.

- **Autorización SIEMPRE en el backend.** [`RequireAuth`](server/internal/httpapi/middleware.go) + [`RequireRole`](server/internal/httpapi/middleware.go) en el router; el front (`web/src/app/roles.ts`) es **solo UX/espejo**, nunca la barrera.
- **Secretos por env, validados al arranque (fail-fast).** [`config.Validate`](server/internal/config/config.go) rechaza `JWT_SECRET` débil/placeholder y `CORS_ORIGIN=*` en producción: la API **no arranca**. Nuevo secreto/config peligrosa → añade su check aquí.
- **Rate limiting en todo endpoint sensible.** [`httpapi.rateLimiter`](server/internal/httpapi/ratelimit.go): per-IP (proxy-safe vía `rateKeyIP`) **y** per-cuenta con lockout. Cableado en `/login` y `/refresh` ([router.go](server/internal/httpapi/router.go)).
- **Eventos de seguridad con clave estable, nunca secretos/PII.** [`logging.SecurityEvent`](server/internal/logging/security.go) para `login_failed`/`pin_failed`/`auth_lockout`/`forbidden`/`refresh_reuse`. PII (customerName/notas) fuera de logs salvo `LOG_LEVEL=debug` o 5xx.
- **Anti-enumeración: iguala la latencia.** En ramas "usuario no encontrado / sin password" corre [`auth.CheckDummySecret`](server/internal/auth/password.go) para no filtrar existencia por temporización.
- **Refresh reuse-detection fail-closed.** [`domain.ClassifyRefresh`](server/internal/domain/refresh.go): si el veredicto es `RefreshReused`, **revoca toda la familia** del usuario + evento de seguridad.
- **Rechaza entradas absurdas como 400, no 500.** [`domain.ValidQty`/`ValidMoney`](server/internal/domain/limits.go) con topes (`MaxOrderQty`, `MaxMoney`) en la frontera: NaN/±Inf, overflow de `numeric`, wrap de `int16` → todos caen como 400/422 limpio.
- **CORS fail-closed.** `CORS_ORIGIN` vacío = solo mismo origen; `*` solo en dev ([`cors`](server/internal/httpapi/router.go)).
- **Todo control de seguridad va con TDD + verificación adversarial** ("¿un atacante lo evade?"). No mergees un control sin su test.

## 6. Testing

- **TDD**: primero el test que falla, luego el código.
- **Extrae la lógica pura a `domain` y pruébala ahí** (sin DB/HTTP). Es la razón de que `domain` no tenga I/O.
- **Table-driven**, tests junto al código (`_test.go` en el mismo paquete). Ejemplos canónicos: [`order_test.go`](server/internal/domain/order_test.go) (`CanTransition`/`BuildOrder`), [`limits_test.go`](server/internal/domain/limits_test.go) (`ValidQty`/`ValidMoney`), [`refresh_test.go`](server/internal/domain/refresh_test.go), [`config_test.go`](server/internal/config/config_test.go), [`ratelimit_test.go`](server/internal/httpapi/ratelimit_test.go).
- **Toda lógica no trivial deja un check runnable.** Si un comentario describe un comportamiento, ese comportamiento **debe** tener test (o el comentario miente cuando el código cambie).

## 7. Disciplina de comentarios (crítico)

- **Comenta el PORQUÉ, nunca el QUÉ.** Intención, tradeoff, restricción no obvia, el ataque que se cierra. Ver el comentario de `rateKeyIP` (por qué el **último** XFF) o de `Round2` (por qué el techo).
- **Prohibido el comentario que reformula el código.** Se desincroniza y termina mintiendo. Si el nombre no basta, arregla el nombre — nombres autoexplicativos primero.
- **Doc-comments estilo Go/Uber**: empiezan con el nombre del símbolo y terminan en punto (`// Validate rejects…`).
- Los atajos deliberados se marcan `// ponytail:` nombrando el techo y el camino de upgrade (ya usado en `ratelimit.go`, `order.go`).

## 8. Patrones a evitar

- **Abstracciones especulativas / YAGNI.** No refunds "por si acaso" (`entregada` es terminal a propósito, ver docs).
- **Interfaces con una sola implementación.** Usa el tipo concreto hasta que exista un segundo consumidor real.
- **Dependencia nueva para lo que hace la stdlib.** El rate limiter, el redondeo y el error-mapping son ~40 líneas propias, no libs.
- **Config para un valor que nunca cambia.** Constante en el código, no env var.

## 9. Dependencias y supply chain

- **Un CVE BLOQUEA y nunca se mergea.** Go: `govulncheck` (pre-push lefthook **+** CI). Frontend: `bun audit --audit-level=high` (**bloqueante** en CI, sin `|| true`). Ya configurado — no lo aflojes.
- **Frescura ≠ pre-commit.** Actualizar deps al día lo maneja **Dependabot** ([.github/dependabot.yml](.github/dependabot.yml)): github-actions, gomod (`/server`), **bun** (`/web`, no `npm`: es lo único que actualiza `bun.lock`) y docker (`/server`+`/deploy`), semanal. Chequeo manual: `go list -u -m all` (Go), `bun outdated` (web). **No** añadas un pre-commit de "deps desactualizadas" (ruidoso, bloquea cambios ajenos).
- **Pin fuerte**: imágenes base por **digest** (`server/Dockerfile`, `deploy/Dockerfile.web`), GitHub Actions por **SHA** ([ci.yml](.github/workflows/ci.yml)), toolchain Go fijado en `go.mod` (`toolchain go1.25.12`).
- **KNOWN NON-ISSUE (no lo "arregles"):** el aviso de deprecación de `golang.org/x/crypto/blowfish` que aparece dentro de `x/crypto/bcrypt` es **esperado** — bcrypt usa blowfish internamente. `bcrypt.GenerateFromPassword` ([auth.HashSecret](server/internal/auth/password.go)) es la forma correcta y vigente de hashear passwords y **no** está deprecada. No lo cambies por AES ni otro cifrado.

## 10. Commits / PR

Los hooks de **lefthook** deben quedar **verdes** antes de commitear/pushear ([lefthook.yml](lefthook.yml)):

- **pre-commit**: `gofmt`, golangci-lint (+ gosec), web lint + typecheck.
- **pre-push**: `go test ./...`, `govulncheck`, `bun run build`.

No hagas `--no-verify`. Si un hook falla, arregla la causa. Commits pequeños y enfocados.
