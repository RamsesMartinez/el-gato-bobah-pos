# El Gato Bobah POS Constitution

Los **principios** de ingeniería del repo viven aquí y **solo aquí**. `AGENTS.md` es la cara
operativa (stack, comandos, quirks de tooling) y hace import de este archivo; no repite ninguna
regla. Cada principio es concreto y verificable, y cita un ejemplo real (`archivo:símbolo`):
ante duda, el código manda.

## Core Principles

### I. Layering estricto (NO NEGOCIABLE)

Request → **`httpapi`** (handler fino) → **`app`** (servicio, orquesta + tx) → **`store/db`** (sqlc);
la lógica pura vive en **`domain`**.

- **`httpapi/`** — handlers finos: decodifican body, construyen el `cmd`, llaman al servicio, mapean el error y responden JSON. Sin lógica de negocio. Ej.: [`Handlers.CreateOrder`](../../server/internal/httpapi/handlers_orders.go). Rutas y middleware en [`Router`](../../server/internal/httpapi/router.go).
- **`app/`** — servicios: orquestan dominio + store, manejan transacciones con `store.WithTx(ctx, func(q *db.Queries) error{…})`. Ej.: [`OrdersService.Cancel`](../../server/internal/app/orders.go).
- **`domain/`** — **puro, sin I/O** (nada de DB/HTTP/red): tipos, sentinels, reglas y cálculo. Ej.: [`BuildOrder`](../../server/internal/domain/order.go), [`CanTransition`](../../server/internal/domain/order.go). Una transición de orden se decide en `domain.CanTransition`, no en el handler.
- **`store/db/`** — **generado por sqlc** (`// Code generated by sqlc. DO NOT EDIT.`). Cambias `queries/*.sql` + `make sqlc`, nunca el `.go`. **SQL solo vía sqlc**: nunca concatenes ni interpoles SQL a mano — todo parametrizado.
- Migraciones goose **embebidas** en el binario. **Redis es solo caché de menú** (y contadores de rate limit) — nunca fuente de verdad: si se cae, el sistema degrada, no se detiene.

Todo plan debe declarar en qué capa aterriza cada pieza.

### II. Errores envueltos, contexto propagado

- **Envuelve con `%w` y usa sentinels de `domain`.** Ej.: `fmt.Errorf("%w (id %d)", ErrProductNotSell, in.ProductID)` en [order.go](../../server/internal/domain/order.go); el mapeo a HTTP vive **solo** en [`httpapi.Error`](../../server/internal/httpapi/respond.go) vía `errors.Is`. No repartas `http.Error` por los handlers.
- **`context.Context` es el primer parámetro y se propaga** hasta la query (pgx lo respeta). Nunca `context.Background()` dentro de un request.
- Sin fugas de goroutines: toda goroutine tiene una condición de término (ctx o cierre de canal).

### III. Dinero redondeado y validado en cada frontera

Dinero = `float64` en **pesos**, redondeado en cada frontera con [`domain.Round2`](../../server/internal/domain/money.go) (2dp) / `Round4` (stock, 4dp) y validado con `domain.ValidMoney` antes de tocar una columna `numeric`. No son centavos enteros; el techo conocido está documentado en `money.go` (migrar a `int64` si el redondeo falla en sumas grandes). El servidor **siempre** recalcula precios; los que manda el cliente se ignoran ([`BuildOrder`](../../server/internal/domain/order.go)).

### IV. Test-first, con la lógica extraída a `domain` (NO NEGOCIABLE)

- **TDD**: primero el test que falla, luego el código.
- **Extrae la lógica pura a `domain` y pruébala ahí** (sin DB/HTTP). Es la razón de que `domain` no tenga I/O.
- **Table-driven**, tests junto al código (`_test.go` en el mismo paquete). Ejemplos canónicos: [`order_test.go`](../../server/internal/domain/order_test.go) (`CanTransition`/`BuildOrder`), [`limits_test.go`](../../server/internal/domain/limits_test.go), [`refresh_test.go`](../../server/internal/domain/refresh_test.go), [`config_test.go`](../../server/internal/config/config_test.go), [`ratelimit_test.go`](../../server/internal/httpapi/ratelimit_test.go).
- **Toda lógica no trivial deja un check runnable.** Si un comentario describe un comportamiento, ese comportamiento **debe** tener test (o el comentario miente cuando el código cambie).
- Un task de implementación sin su task de test antes está mal ordenado.

### V. Seguridad verificada adversarialmente (NO NEGOCIABLE)

Este repo pasó una auditoría OWASP + una segunda ronda adversarial ([docs/security-owasp.md](../../docs/security-owasp.md)). Estos helpers **ya existen**: úsalos, no reinventes.

- **Autorización SIEMPRE en el backend.** [`RequireAuth`](../../server/internal/httpapi/middleware.go) + [`RequireRole`](../../server/internal/httpapi/middleware.go) en el router; el front (`web/src/app/roles.ts`) es **solo UX/espejo**, nunca la barrera.
- **Secretos por env, validados al arranque (fail-fast).** [`config.Validate`](../../server/internal/config/config.go) rechaza `JWT_SECRET` débil/placeholder y `CORS_ORIGIN=*` en producción: la API **no arranca**. Nuevo secreto/config peligrosa → añade su check aquí.
- **Rate limiting en todo endpoint sensible.** [`httpapi.rateLimiter`](../../server/internal/httpapi/ratelimit.go): per-IP (proxy-safe vía `rateKeyIP`) **y** per-cuenta con lockout, cableado en `/login`, `/refresh`, `/forgot` y `/reset`. Backed por Redis cuando `REDIS_URL` está definido; sin Redis cae a in-memory (dev). Redis caído = **fail-open** (nunca tumba login por un hiccup del caché), logueado como evento de seguridad.
- **Eventos de seguridad con clave estable, nunca secretos/PII.** [`logging.SecurityEvent`](../../server/internal/logging/security.go) para `login_failed`/`pin_failed`/`auth_lockout`/`forbidden`/`refresh_reuse`. PII (customerName/notas) fuera de logs salvo `LOG_LEVEL=debug` o 5xx.
- **Anti-enumeración: iguala la latencia.** En ramas "usuario no encontrado / sin password" corre [`auth.CheckDummySecret`](../../server/internal/auth/password.go) para no filtrar existencia por temporización.
- **Refresh reuse-detection fail-closed.** [`domain.ClassifyRefresh`](../../server/internal/domain/refresh.go): si el veredicto es `RefreshReused`, **revoca toda la familia** del usuario + evento de seguridad.
- **Rechaza entradas absurdas como 400, no 500.** [`domain.ValidQty`/`ValidMoney`](../../server/internal/domain/limits.go) con topes (`MaxOrderQty`, `MaxMoney`) en la frontera: NaN/±Inf, overflow de `numeric`, wrap de `int16` → todos caen como 400/422 limpio.
- **CORS fail-closed.** `CORS_ORIGIN` vacío = solo mismo origen; `*` solo en dev ([`cors`](../../server/internal/httpapi/router.go)).
- **Ningún control de seguridad se mergea sin su test** y sin haber respondido "¿un atacante lo evade?" con un caso concreto, no con teoría.

### VI. YAGNI — el código más simple que resuelve el caso de hoy

- **Sin abstracciones especulativas.** No refunds "por si acaso" (`entregada` es terminal a propósito).
- **Sin interfaces de una sola implementación.** Usa el tipo concreto hasta que exista un segundo consumidor real.
- **Sin dependencia nueva para lo que hace la stdlib.** El rate limiter, el redondeo y el error-mapping son ~40 líneas propias, no libs.
- **Sin config para un valor que nunca cambia.** Constante en el código, no env var.
- Los atajos deliberados se marcan `// ponytail:` nombrando el techo y el camino de upgrade (ya usado en `ratelimit.go`, `order.go`).
- Aplica al alcance de un spec tanto como al código: una feature que "por si acaso" abre tres extensiones futuras está mal recortada.

### VII. Los comentarios explican el porqué

- **Comenta el PORQUÉ, nunca el QUÉ.** Intención, tradeoff, restricción no obvia, el ataque que se cierra. Ver el comentario de `rateKeyIP` (por qué el **último** XFF) o de `Round2` (por qué el techo).
- **Prohibido el comentario que reformula el código.** Se desincroniza y termina mintiendo. Si el nombre no basta, arregla el nombre — nombres autoexplicativos primero.
- **Doc-comments estilo Go/Uber**: empiezan con el nombre del símbolo y terminan en punto (`// Validate rejects…`).

## Restricciones del producto

- **Target: tablets de 7"** — el tamaño de los controles táctiles y la separación de las acciones destructivas son requisito funcional, no preferencia estética. La vara de UX del POS es **minimizar taps**: nunca obligar al operador a deshacer para rehacer.
- **El texto de la interfaz es para quien opera el negocio, no para quien lo programa.** Este producto se vende. Una pantalla que justifica *por qué* una decisión técnica es la correcta, o que argumenta contra la alternativa, delata al desarrollador y resta confianza en el producto. En pantalla va lo que el operador necesita para decidir; el porqué vive en el comentario del código o en `docs/`.
  - **Prohibido en la UI**: justificar un tradeoff ("peor que el toque que esto viene a quitar"), nombrar internals (flags del navegador, endpoints, columnas) o advertir de algo que el usuario no puede accionar desde ahí.
  - **El detalle operativo que sí sirve** —cómo dejar la tablet lista, qué formato de imagen se acepta— se guarda detrás de un icono de ayuda y se redacta como instrucción en pasos, no como explicación. Ej.: el interruptor de impresión automática en [`PrintSettingsPage`](../../web/src/features/admin/PrintSettingsPage.tsx) dice qué hace en un renglón y deja el "cómo configurarlo" en un diálogo de ayuda.
  - Vara para revisar una pantalla: **si el renglón solo tiene sentido para alguien que leyó el código, no va.**
- **Producción con datos reales de un negocio en operación.** Ante la duda, gana la opción que no pierde datos ni tumba el servicio, aunque sea la más lenta de construir.
- **Dependencias siempre en la última versión estable**, y **un CVE bloquea el merge**: `govulncheck` (Go) y `bun audit --audit-level=high` (web) son bloqueantes en CI y no se aflojan.

## Quality gates

- **`/speckit-analyze` corre antes de `/speckit-implement`, siempre.** El flujo publicado lo marca opcional; en este repo no lo es. Un hallazgo CRITICAL o HIGH bloquea la implementación hasta resolverse o hasta que el dueño lo exima explícitamente.
- **Los hooks de lefthook quedan verdes** antes de commitear o pushear. `--no-verify` no se usa: si un hook falla, se arregla la causa. (Qué corre cada hook: `AGENTS.md`.)
- **Verificación de backend antes de dar algo por bueno**: `make api-build && make api-test`.
- Commits pequeños y enfocados.
- **Cada commit va firmado y con autoría única.** Firma GPG verificable (`git log -1 --pretty=%G?` → `G`) y **un solo autor**: el dueño del repo. **Ningún trailer `Co-Authored-By`**, tampoco cuando el commit lo escribió un agente — la firma responde por quién hizo el cambio y un co-autor que no puede firmar la contradice. (Llave, `git config` y ajuste del harness: `AGENTS.md`.)

## Governance

Esta constitución es la fuente única de los principios y **prevalece sobre cualquier conveniencia
de un spec o plan individual**. Un plan que viole un principio no negociable no se implementa: se
corrige el plan, o se enmienda la constitución primero — nunca se implementa la excepción en
silencio.

`AGENTS.md` no repite estas reglas; documenta la mecánica del repo (stack, comandos, quirks de
tooling, supply chain) e importa este archivo para que los principios estén en contexto también
fuera del ciclo de spec-kit. Si una regla aparece en los dos archivos, es un bug de documentación:
se borra de `AGENTS.md`.

Las enmiendas van en un commit propio que dice qué principio cambia y por qué. La versión sigue
semver: **MAJOR** si se elimina o se invierte un principio, **MINOR** si se agrega uno o una
sección, **PATCH** si es redacción o una cita de código. Al enmendar, verifica que los símbolos
citados existan y que los subagentes de `.claude/agents/` y `.codex/agents/` sigan apuntando al
principio correcto.
